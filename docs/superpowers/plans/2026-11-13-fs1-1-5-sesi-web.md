# FS-1 1.5 — Sesi web, CSRF, penyajian bundel, dan CSP: rencana implementasi

> **Untuk agen pelaksana:** SUB-SKILL WAJIB: superpowers:subagent-driven-development (disarankan) atau superpowers:executing-plans. Langkah memakai kotak centang (`- [ ]`).

**Tujuan:** biner `casa` melayani bundel web tersemat dari satu origin dengan CSP dan header keamanan pada setiap jawaban, dan klien web mendapat sesi lewat satu cookie `__Host-` (mode pribadi dan bersama, rotasi, umur), dengan pemeriksaan permintaan lintas situs, sehingga 1.9b dan 1.10 dapat menyambungkan klien ke server.

**Arsitektur:** paket baru `internal/webbundle` hanya menyematkan `dist/` (salinan `web/build`, diisi `make casa`). `internal/api` mendapat `Bundle` (penyaji berkas statis dengan aturan cache, MIME tetap, ETag, fallback SPA) dan pembungkus header keamanan yang membungkus seluruh mux, sehingga jawaban Connect, galat, 404, dan berkas statis membawa header yang sama. Interseptor batas 1.3/1.4 mendapat jalur cookie: pemeriksaan origin, autentikasi cookie, pencocokan jenis klien, dan sentuhan diam mode bersama dari `user_initiated`. `identity` membuka sesi web (cookie, `device_mode`, `ua_summary`), mengautentikasi dan memutar nilai cookie. Biner pengembangan `cmd/webpreview` menyajikan bundel tersemat yang sama dengan header produksi tanpa basis data, dan menjadi server Playwright, sehingga semua uji e2e berjalan di bawah CSP produksi.

**Stack:** Go (toolchain di `server/go.mod`), stdlib (`embed`, `net/http`, `crypto/sha256`), connect-go v2 (`connecthttp.ServerInfoForContext` untuk metode HTTP), pgx v5, goose v3, sqlc; Playwright (sudah terpasang) untuk Chromium dan WebKit. **Tanpa dependensi baru** di Go maupun npm.

**Spesifikasi:** 14 §3.3 langkah 1 (kolom server, kalimat "Web:"); 10.5 §2 SEC-160, SEC-161, SEC-162, SEC-164 (b), §3 SEC-165 (a), (g), §4 SEC-166, SEC-167 (c), SEC-169 (a), (b); ADR-030 butir 3, 5, 6, 7, 9; 09.2 §1, §3, §5.1 (`session`), §10; 09.4 §1 ("Bundel web"), §2 ("Sesi klien web", "CSRF klien web"), §4 ("Keamanan klien web"); 09.3 §1; `_progress.md` "FS-1 1.4 selesai" (ke tugas berikutnya), "FS-1 1.9a selesai"; rencana 1.4 "Yang sengaja tidak di tugas ini" butir 1; `ENGINEERING-STANDARDS.md` §1 sampai §9.

**Pelaksana:** `backend-dev` (Tugas 1, 3 sampai 7); `web-dev` (Tugas 2, bagian `web/` dan CI web; bagian Go `cmd/webpreview` ditulis `backend-dev` di Tugas 1). **Peninjau:** `code-reviewer` (dua lintasan) per PR; `ux-designer` tidak terlibat (tanpa layar). **Cabang:** `fs1/1.5a-bundle` (PR A, Tugas 1 sampai 2) dan `fs1/1.5b-web-session` (PR B, Tugas 3 sampai 7, dari `main` sesudah PR A di-merge) **(Q10)**.

## Keputusan yang diambil rencana ini

Butir bertanda **(Qn)** memakai rekomendasi rencana sambil menunggu putusan lead atas Qn di akhir.

1. **Bundel tersemat.** `server/internal/webbundle/webbundle.go`: `//go:embed all:dist` `var FS embed.FS`. `dist/` di-gitignore kecuali `dist/.gitkeep`, jadi paket selalu terkompilasi. `make casa` membangun `web/` (`pnpm build`), mengosongkan `dist/` (kecuali `.gitkeep`), menyalin `web/build/.`, lalu `go build -trimpath -o .cache/casa ./cmd/casa`. Berkas berawalan `.` di mana pun dalam bundel tidak pernah disajikan (`.gitkeep`, `.well-known`).
2. **Tanpa bundel (Q5):** `NewBundle` tanpa `index.html` mengembalikan `ErrNoBundle`; `casa serve` lalu mencetak satu baris `casa serve: no web bundle in this binary; build it with make casa` ke stderr dan tetap melayani API (rute statis 404), supaya uji server dan pengembangan API tanpa build web tetap jalan. Biner rilis (langkah 7) selalu dibangun dengan `make casa`; runbook mencocokkan hash.
3. **Penyajian statis** (SEC-166, SEC-169 (b); ADR-030 butir 7, 9), hanya `GET` dan `HEAD`:
   - jalur dibersihkan (`path.Clean`), awalan `/` dibuang, `""` menjadi `index.html`;
   - berkas ada (bukan direktori, tanpa segmen berawalan `.`) → disajikan dengan `http.ServeContent`;
   - tidak ada, dan segmen terakhir tanpa titik serta jalur tidak diawali `_app/` → `index.html` (fallback SPA, 200);
   - selain itu 404 teks polos. Tidak pernah daftar direktori, tidak pernah HTML untuk aset yang hilang.
   - `Cache-Control`: berkas di bawah `_app/immutable/` → `public, max-age=31536000, immutable`; semua berkas statis lain, termasuk `index.html` dan `service-worker.js` → `no-cache` **(Q8)**.
   - `Content-Type` dari peta tetap di kode, bukan `mime.TypeByExtension` (yang membaca `/etc/mime.types` mesin sehingga berbeda di VPS): `.html` `text/html; charset=utf-8`, `.js` `text/javascript; charset=utf-8`, `.css` `text/css; charset=utf-8`, `.json` `application/json`, `.webmanifest` `application/manifest+json`, `.png` `image/png`, `.svg` `image/svg+xml`, `.woff2` `font/woff2`, `.ico` `image/x-icon`, `.txt` `text/plain; charset=utf-8`. Ekstensi lain di bundel → `NewBundle` gagal (gagal saat mulai, bukan saat disajikan).
   - `ETag` kuat: 16 karakter heksadesimal pertama SHA-256 isi berkas, dihitung sekali di `NewBundle`; `ServeContent` menjawab `If-None-Match` dengan 304.
4. **Hash skrip pembuka (Q9).** SvelteKit SPA mengeluarkan satu skrip inline di `index.html` (terlihat di build 13 November 2026). `NewBundle` mengambil isi setiap `<script>` tanpa atribut di `index.html`, menghitung `'sha256-<base64 std>'` atas byte persis di antara `<script>` dan `</script>`, dan menambahkannya ke `script-src`. `<script` lain di `index.html` yang tidak memuat atribut `src=` → `NewBundle` gagal. Karena byte `index.html` tetap di dalam biner, hash yang dihitung saat mulai sama dengan hash saat build (ADR-030 butir 7 "lewat hash build"); tidak ada `'unsafe-inline'` di `script-src`.
5. **Header keamanan pada setiap jawaban** (SEC-160 (c), SEC-166; ADR-030 butir 7), dipasang pembungkus `WithSecurityHeaders` sebelum handler apa pun menulis:

   | Header | Nilai |
   |---|---|
   | `Content-Security-Policy` | `default-src 'none'; script-src 'self' <hash…>; style-src 'self'; img-src 'self' blob:; font-src 'self'; connect-src 'self'; worker-src 'self'; manifest-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'; object-src 'none'; require-trusted-types-for 'script'; trusted-types svelte-trusted-html casa-sw` |
   | `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` |
   | `X-Content-Type-Options` | `nosniff` |
   | `Referrer-Policy` | `no-referrer` |
   | `Cross-Origin-Opener-Policy` | `same-origin` |
   | `Cross-Origin-Resource-Policy` | `same-origin` |
   | `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=(), usb=()` |
   | `Cache-Control` | bawaan `no-store` (API, galat, `/healthz`, 404); penyaji statis menimpanya menurut butir 3 |

   Tanpa `Access-Control-Allow-*` di jawaban mana pun (SEC-160 (b)). Nama `svelte-trusted-html` tetap sampai prototipe 1.11 memutus apakah Svelte memerlukannya (ADR-030 "Yang menunggu"); 1.5 tidak mengubah direktif. **Bila uji Tugas 2 menemukan pelanggaran CSP oleh layar yang ada, pelaksana berhenti dan melapor ke lead; CSP tidak dilonggarkan di tugas ini.**
6. **Pratinjau pengembangan (Q6).** `server/cmd/webpreview` (tidak pernah di-deploy): `webpreview -listen addr` menyajikan `webbundle.FS` lewat `WithSecurityHeaders(bundle)` saja, tanpa API dan basis data. Playwright memakainya menggantikan `vite preview`, sehingga semua uji e2e berjalan atas byte bundel tersemat dan header produksi. Job CI `web` mendapat `actions/setup-go` (dipatok SHA, versi dari `server/go.mod`, seperti job `server`).
7. **Cookie sesi (Q7):** nama `__Host-casa_session`, nilai token 43 karakter (keputusan 5 rencana 1.4), atribut `Path=/; Secure; HttpOnly; SameSite=Strict`, tanpa `Domain`. Mode pribadi: `Max-Age` = sisa umur mutlak dalam detik, dibulatkan ke bawah, dihitung ulang setiap kali cookie dipasang. Mode bersama: tanpa `Max-Age` dan `Expires`. Dibuat dengan `http.Cookie{…}.String()`, dipasang lewat `connect.CallInfo.ResponseHeader().Add("Set-Cookie", …)`.
8. **Umur sesi web** (SEC-161 (d), SEC-165 (a); 09.4 §2): pribadi diam 30 hari, mutlak 180 hari; bersama diam 30 menit, mutlak 12 jam. Native tidak berubah.
9. **`device_mode` di kontrak (Q4).** Enum `DeviceMode { DEVICE_MODE_UNSPECIFIED = 0; DEVICE_MODE_PERSONAL = 1; DEVICE_MODE_SHARED = 2; }` di `identity.proto`, medan `DeviceMode device_mode = 4` di `SignInRequest`, `CompleteSignUpRequest`, `CompleteRecoveryRequest`, dengan satu aturan CEL tingkat pesan: `this.request_context.client_kind == 3 ? this.device_mode != 0 : this.device_mode == 0` (id `device_mode.web`, pesan `"web clients choose a device mode; native clients send none"`). Web wajib memilih (SEC-165: tanpa pilihan terpilih); native tidak mengirim apa pun dan sesinya `personal`. Respons ketiga RPC itu untuk web: medan `tokens` tidak diisi; sesi hanya lewat `Set-Cookie` (SEC-161 (b)).
10. **`ua_summary` web (Q3, dikukuhkan `security-privacy` dengan koreksi; SEC-161 (e) catatan 13 November 2026):** `"<browser> · <sistem>"` dari `User-Agent` dengan daftar tetap, paling banyak 64 karakter. Browser diperiksa dengan urutan ini: Edge (`Edg/`), Samsung Internet (`SamsungBrowser/`), Firefox (`Firefox/` atau `FxiOS/`), Chrome (`Chrome/` atau `CriOS/`), Safari (`Safari/` dan `Version/`), selain itu `Browser` (User-Agent Edge dan Samsung memuat "Chrome", Chrome memuat "Safari"). Sistem: iOS (`iPhone`), iPadOS (`iPad`), Android, Windows, **`macOS/iPadOS`** (`Macintosh`: Safari iPad meminta situs desktop secara bawaan, dan pilot memakai iPad mini 7), Linux, selain itu `Other`. Tanpa nomor versi (minimisasi). Karena keluarannya hanya dari daftar tetap, isi User-Agent tidak pernah tersimpan atau tercatat; Client Hints tidak diminta. Native tetap `''`. Label cadangan `Browser` dan `Other` tampil ke pengguna, jadi kata Indonesianya milik `ux-designer` (08) di tugas daftar sesi; 1.5 menyimpan label sementara ini.
11. **Jalur cookie di batas** (SEC-162; ADR-030 butir 6). Urutan baru interseptor:
    1. deskriptor metode (tetap);
    2. **pemeriksaan origin pra-isi**: bila permintaan membawa cookie `__Host-casa_session`, header `Origin`, atau header `Sec-Fetch-Site` (prosedur apa pun, jenis klien apa pun: `client_kind` diisi pengirim, jadi halaman lintas situs dapat mengaku `ios`; SEC-162 (a) catatan 13 November 2026), maka metode HTTP harus `POST` (`connecthttp.ServerInfoForContext(ctx).HTTPMethod()`), `Origin` harus ada dan sama persis (perbandingan string) dengan `-origin` server, dan `Sec-Fetch-Site`, bila ada, harus `same-origin`; selain itu `CodePermissionDenied` `"cross-origin request rejected"` tanpa detail, sebelum isi dibaca;
    3. di luar `publicProcedures`: `Authorization: Bearer` ada → jalur native (tetap); tidak ada dan cookie ada → `AuthenticateCookie`; keduanya tidak ada → `Unauthenticated`. Cookie baru dari autentikasi dipasang di header jawaban di sini, sehingga ikut terkirim walau handler gagal;
    4. `request_context` (tetap);
    5. **baru:** `client_kind = WEB` → pemeriksaan origin langkah 2 juga, sehingga RPC web tanpa `Origin` ditolak (menutup CSRF masuk pada RPC publik web; Q2 dikukuhkan `security-privacy`); permintaan yang terautentikasi → jenis klien di `request_context` harus sama dengan `session.client_kind`, selain itu `CodeInvalidArgument` `"client kind does not match the session"`; sesi web mode bersama dengan `user_initiated = true` → `TouchUserAction`;
    6. sampai 8: versi minimum, kunci idempotensi, validasi penuh (tetap).

    `GET` Connect tidak pernah diterima: tidak ada metode berlevel `NO_SIDE_EFFECTS` (connect-go hanya membuka `GET` untuk level itu), dan langkah 2 menolaknya bagi cookie bila kelak ada.
12. **Rotasi cookie (Q1, diputus `security-privacy` 13 November 2026: rekomendasi diterima dengan tiga tambahan; SEC-161 (c) catatan FS-1 tugas 1.5 aturan (1) sampai (5)).** Alasan: jawaban yang membawa `Set-Cookie` dapat hilang (web app iPhone ditangguhkan saat permintaan berjalan); tanpa aturan ini pengguna sah kehilangan sesi, dan `session_revoked` menghapus antrean catatan yang belum terkirim (SEC-172). Nilai yang dibawa permintaan digolongkan terhadap satu baris `session`:
    - **sekarang** (`token_hash`): bila `token_confirmed_at` kosong, diisi (nilai terbukti diterima browser). Bila `now − token_issued_at ≥ 15 menit` → rotasi: nilai baru; nilai sekarang menjadi `prev_token_hash` dengan `prev_valid_until = now + 60 detik`; `token_confirmed_at` dikosongkan.
    - **sebelumnya**, di dalam jendela: diterima tanpa rotasi.
    - **sebelumnya**, sesudah jendela: nilai sekarang terkonfirmasi → sesi dicabut `reuse_detected` dan satu `security_event`; belum terkonfirmasi → **terbitkan ulang**: nilai sekarang (yang tidak pernah sampai) dibuang dan hash-nya disimpan di `discarded_token_hash`, nilai baru diterbitkan, nilai yang dibawa tetap `prev` dengan jendela 60 detik baru; tanpa pencabutan dan tanpa `security_event`.
    - **dibuang** (`discarded_token_hash`): sesi dicabut `reuse_detected` dan satu `security_event` (aturan (3): browser yang tidak pernah menerima nilai tidak dapat membawanya, jadi tanpa positif palsu; menutup pembajakan diam ketika penyerang membawa nilai lama lebih dulu).
    - **tak dikenal**: `ErrUnauthenticated` (masuk lagi), **tidak pernah** `session_revoked`, sehingga data lokal tetap (aturan (5)).
    - **Satu keputusan per baris** (aturan (4)): penggolongan dan setiap tulisan dalam satu transaksi `database.Write` yang mengunci baris (`SELECT … FOR UPDATE` lewat sqlc), sehingga dua permintaan serentak dengan nilai lama menghasilkan tepat satu penerbitan ulang dan yang kedua diterima sebagai nilai sebelumnya di jendela baru. Pembacaan pencarian (tanpa kunci) hanya menemukan `account_id` (10.1 §5.1); keputusan dibuat di transaksi tulis dengan `Scope{AccountID, TokenHash}`.
    - Rotasi paksa saat masuk (sesi baru), pemulihan (sesi baru), dan autentikasi ulang web (`RotateCookie`).
    - Sisa risiko yang dinyatakan di SEC-161 (c): pemakaian di dalam jendela 60 detik tidak terdeteksi; sesudah jendela, penyerang terdeteksi pada permintaan berikut pihak lain; kegagalan ganda yang jarang (permintaan nilai lama tiba > 60 detik sesudah rotasi **dan** jawabannya juga hilang) dapat mencabut sesi sah, diterima.
13. **Sentuhan diam.** Mode pribadi: seperti native (`touchAfter` 1 menit) di `AuthenticateCookie`. Mode bersama: `AuthenticateCookie` tidak pernah menyentuh; hanya `TouchUserAction` (langkah 5 butir 11) yang memperbarui `last_used_at`, bila `now − last_used_at > touchAfter` (SEC-165 (g)). Batas mutlak tidak pernah bergeser.
14. **Keluar akun web** (SEC-164 (b)): jawaban `SignOut` untuk sesi cookie membawa `Clear-Site-Data: "cookies", "storage"` (tanpa `"cache"`) dan cookie kedaluwarsa (`Max-Age=0`, atribut sama). Penghapusan langganan push sesi itu menunggu tabel langganan (langkah 4).
15. **Migrasi `00004_web_session.sql`** (expand saja, aman bagi biner lama, 09.2 §10): kolom `session.token_confirmed_at timestamptz NULL` dan `session.discarded_token_hash bytea NULL`; indeks `session_prev_token ON session (prev_token_hash) WHERE prev_token_hash IS NOT NULL` dan `session_discarded_token ON session (discarded_token_hash) WHERE discarded_token_hash IS NOT NULL`; kebijakan `session` diganti dengan dua klausa pencarian tambahan di `USING` saja: `OR prev_token_hash = decode(nullif(current_setting('app.token_hash', true), ''), 'hex') OR discarded_token_hash = decode(…sama…)`, dan uji RLS 10.1 §5.1 aturan 7 mencakup keduanya; `GRANT UPDATE (prev_token_hash, prev_valid_until, token_confirmed_at, discarded_token_hash) ON session TO app_rw`. Tanpa hibah `UPDATE` untuk `device_mode` dan `ua_summary`: mode tidak berubah di tengah sesi (SEC-165). Down membalik semuanya.

## Batasan global

- Batasan global 1.1a sampai 1.4 berlaku: ES §1 sampai §9; alat dicek live saat dipasang (ES §8); `actions/setup-go` di job `web` dipatok SHA yang sama dengan job `server`.
- Tanpa dependensi baru (Go dan npm). Tanpa log baru; tidak ada nilai cookie, token, atau User-Agent di galat yang sampai ke klien, di keluaran `casa`/`webpreview`, atau di pesan galat Go yang dapat tercetak (SEC-44; SEC-161 (b)).
- Semua SQL produksi lewat sqlc, berparameter; setiap kueri baru punya indeks yang melayaninya, `EXPLAIN` dilampirkan di PR (ES §3).
- Uji basis data memakai PostgreSQL 18 nyata, gagal keras tanpa `CASA_TEST_ADMIN_URL`. Uji tidak memakai `t.Parallel` di `identity`, `command`, `api`. Jam uji lewat `identity.Config.Now`, tanpa tidur.
- Nama uji yang menyebut ID diawali ID-nya (QG-06) hanya bila uji membuktikan ID itu utuh; bagian ID dikutip di komentar.
- Pengenal mengikuti glosarium (mode perangkat bersama = `shared`, mode pribadi = `personal`; jejak keamanan = `security_event`). Komentar, pengenal, pesan commit berbahasa Inggris; setiap aturan di kode mengutip ID atau bagian dokumennya.
- Jalankan per paket saat iterasi: `cd server && CASA_TEST_ADMIN_URL='postgres://postgres@127.0.0.1:5432/postgres?sslmode=disable' go test -race -p 1 -run '<Uji>' ./internal/<paket>/`; `make check` hanya di langkah verifikasi.

## Fokus tinjauan

1. **Cookie baru yang hilang mencabut sesi sah dan menghapus antrean** (butir 12). Uji Tugas 5: rotasi terjadi, jawaban "hilang" (klien uji membuang `Set-Cookie`), nilai lama dipakai pada detik ke-61 → dilayani dengan nilai baru, sesi tidak dicabut, tanpa `security_event`; nilai baru dipakai sekali, lalu nilai lama pada detik ke-61 → `SESSION_REVOKED`.
2. **Pemeriksaan origin yang dapat dilewati.** Staging di subdomain (SEC-41 (d)) adalah *same-site*, jadi `SameSite=Strict` tidak menahannya; hanya pemeriksaan origin yang menahan. Uji Tugas 4: `Origin` staging (`https://staging.<host>`), `null`, beda port, `http` lawan `https`, garis miring di akhir, huruf besar host, `Sec-Fetch-Site: same-site` dengan `Origin` benar, cookie dengan `Authorization` sekaligus, dan RPC publik web tanpa `Origin`: semuanya ditolak tanpa efek di basis data.
3. **Fallback SPA menyajikan HTML untuk aset atau keluar dari bundel.** Uji Tugas 1: `/_app/immutable/missing.js` → 404 teks; `/../../go.mod`, `/%2e%2e/x`, `/.gitkeep`, `/_app/` (direktori) → bukan berkas di luar bundel, bukan daftar direktori; `/manifest.webmanifest` dengan `Content-Type` `application/manifest+json` dan `nosniff`.
4. **Nilai cookie bocor.** Uji Tugas 3: untuk masuk, daftar, dan pulih varian web, badan jawaban tidak memuat nilai cookie (medan `tokens` kosong), dan pemindaian semua kolom tabel `identity` dan `idempotency_record` serta `ua_summary` tidak memuat nilai itu atau isi User-Agent mentah (User-Agent uji berisi penanda unik dan karakter kendali).
5. **Mode bersama diperpanjang oleh kegiatan latar** (SEC-165 (g)). Uji Tugas 4: sesi bersama, RPC tiap 5 menit dengan `user_initiated = false` selama 30 menit → `SESSION_EXPIRED` di menit ke-30; satu RPC `user_initiated = true` di menit ke-29 → masih hidup di menit ke-58, berakhir di menit ke-59; sesi berumur 12 jam berakhir walau ada RPC bertanda.

### Tugas 1: Bundel tersemat, penyaji statis, dan header keamanan

**Berkas:**
- Buat: `server/internal/webbundle/webbundle.go`, `server/internal/webbundle/dist/.gitkeep`, `server/internal/api/bundle.go`, `server/internal/api/bundle_test.go`, `server/internal/api/headers.go`, `server/internal/api/headers_test.go`, `server/cmd/webpreview/main.go`, `server/cmd/webpreview/main_test.go`
- Ubah: `server/internal/api/server.go` (`NewMux`), `server/cmd/casa/serve.go`, `server/cmd/casa/serve_test.go`, `server/internal/architecture/imports_test.go`, `.gitignore`, `Makefile` (target `casa`, `bundle-copy`)

**Antarmuka:**
- Menghasilkan:

```go
package webbundle
var FS embed.FS // //go:embed all:dist

package api
var ErrNoBundle = errors.New("no index.html in the web bundle")
type Bundle struct{ … }                       // files, types, etags, script hashes; immutable after NewBundle
func NewBundle(fsys fs.FS) (*Bundle, error)    // fsys is rooted at the bundle (fs.Sub(webbundle.FS, "dist"))
func (b *Bundle) ServeHTTP(w http.ResponseWriter, r *http.Request)
func WithSecurityHeaders(next http.Handler, bundle *Bundle) http.Handler // bundle nil: no script hashes
func NewMux(server *connect.Server, bundle *Bundle) http.Handler        // bundle nil: static routes 404
```
