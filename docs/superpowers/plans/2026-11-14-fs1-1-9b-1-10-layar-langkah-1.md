# FS-1 1.9b bagian 1 dan 1.10 — klien API web dan layar langkah 1: rencana implementasi

> **Untuk agen pelaksana:** SUB-SKILL WAJIB: superpowers:subagent-driven-development (disarankan) atau superpowers:executing-plans. Langkah memakai kotak centang (`- [ ]`).

**Tujuan:** klien web memanggil server lewat kontrak hasil generate (connect-web), dengan versi klien di setiap permintaan, pemeriksaan sesi saat dibuka, dan penanganan sesi berakhir (1.9b bagian 1). Di atasnya: layar langkah 1 (1.10), yaitu LY-90, LY-91, LY-01 sampai LY-08, LY-92 bagian verifikasi, LY-94, bilah mode bersama, dan alur penerima undangan, sampai kriteria selesai 14 §3.3 langkah 1 tercapai.

**Arsitektur:**
- **Satu modul API** `web/src/lib/api.ts`: transport ke origin sendiri, klien `IdentityService` dan `HouseholdService` hasil generate, interseptor `client_kind`/`client_version`, dan pembaca galat (`ErrorDetail`, `buf.validate.Violations`).
- **Satu keadaan sesi di memori** `web/src/lib/session.svelte.ts`: hasil pemeriksaan, mode, keanggotaan, token yang dipegang. Data layar langkah 1 hanya di memori; IndexedDB dibuat saat masuk mode pribadi (SEC-171 (e)) dan tetap berisi `outbox` dan `meta`. Perintah dikirim daring, di luar antrean (keputusan 1).
- **Layar** satu rute per layar di `web/src/routes/`. Komponen di `web/src/lib/components/`, dibuat sekali saat pertama diperlukan, dengan `tokens.css` dan bentuk §19.13.5. Teks layar di `web/src/lib/copy.ts`.
- **Uji alur:** Playwright di kedua mesin atas bundel di bawah CSP produksi (`cmd/webpreview`), API ditiru `page.route` dengan skema hasil generate; satu uji ujung ke ujung lokal terhadap `casa serve` (ES §9 butir 5).

**Stack:** yang sudah ada (SvelteKit 3.1.1 SPA, Svelte 5, Dexie 4, `@bufbuild/protobuf` 2.17.0, Vitest, Playwright), ditambah `@connectrpc/connect` dan `@connectrpc/connect-web` (bundel; sudah di daftar ADR-030 butir 8). Dicek live 14 November 2026: 2.3.0, rilis 27 Oktober 2026 (18 hari), Apache-2.0, peer `@bufbuild/protobuf ^2.7.0` terpenuhi ([registry.npmjs.org/@connectrpc/connect-web](https://registry.npmjs.org/@connectrpc/connect-web)); dicek ulang saat dipasang (ES §8). Tanpa dependensi pengembangan baru. Alat pratinjau di PC (bukan dependensi repositori): Caddy v2.11.9, rilis 5 November 2026, Apache-2.0 ([github.com/caddyserver/caddy/releases](https://github.com/caddyserver/caddy/releases)).

## Keputusan yang diambil rencana ini

1. **Perintah langkah 1 daring, di luar antrean:** semuanya "Tindakan yang memerlukan server" (08 §13.2; FR-FAM-001/AC-6; SEC-164 (a)). Pengikatan `send` antrean dan pengatur waktu coba ulang ADR-030 butir 10 pindah ke 1.9b bagian 2.
2. **Transport:** `createConnectTransport({ baseUrl: location.origin, useBinaryFormat: true })`, `fetch` dan `credentials` bawaan. Tidak ada header tambahan: `Origin` dan `Sec-Fetch-Site` dari browser, cookie tidak terbaca skrip (SEC-161 (b), SEC-162 (b)).
3. **Versi klien:** `"version": "0.1.0"` di `web/package.json` → `__CASA_VERSION__`; pola diuji dari deskriptor kontrak, seperti `server/internal/api/version.go`.
4. **Pemeriksaan sesi saat dibuka = `ListMemberships`**, dibatasi 3 detik (SEC-172 (b)). Hasilnya juga dipakai untuk memilih layar. PR E menggantinya dengan `GetSession` (putusan Q3 (a); ADR-030 butir 10, catatan 14 November 2026).
5. **Mode saat dibuka ulang, sementara sampai PR E:** basis data `casa` ada → mode pribadi; sesi sah tanpa basis data → mode bersama. Di langkah 1 tidak ada data tersimpan selain antrean kosong.
6. **LY-94 tampil di tempat, tanpa muat ulang** (putusan lead 1.9a butir 4): `{n}` dihitung `broadcastWipe` sebelum hapus dan dibawa pesan siaran; `resetSessionState()` sebelum LY-94 dirender; "Masuk" = `location.replace('/')` (SEC-164 (c)).
7. **Daftar mengikuti kontrak:** `StartSignUp` membawa email dan token; kata sandi dan mode diisi di halaman verifikasi (`CompleteSignUp`, rencana 1.4). 08 §5.1 LY-02 sudah disesuaikan (08 §7.6, catatan 14 November 2026). Klien tidak memeriksa panjang kata sandi atau bentuk email sendiri; pelanggaran `buf.validate` dari server dipetakan ke medannya. Satu-satunya bantuan isian klien adalah panjang nama (ES §2 (c)).
8. **Tautan token** (SEC-175 (c)): `/signup#t` (pemasangan), `/signup/verify#t` (jalur `identity/signup.go`), `/invite#t` (jalur kontrak). `history.replaceState` membuang fragmen sebelum RPC apa pun. Token hanya di `session.pendingToken` (memori). `casa setup-token -origin <origin>` mencetak tautan `<origin>/signup#<token>` (09.4 §2, catatan 14 November 2026). Isian tempel menerima tautan undangan dan pemasangan (SEC-175 (c) (1) sampai (4)).
9. **Pernyataan usia:** buat rumah tangga dan terima undangan dikirim dengan `age_declaration_version: 0`, kecuali LY-04 sudah dicentang di sesi ini. `AGE_DECLARATION_REQUIRED` membuka LY-04, lalu perintah dikirim ulang dengan versi `1` dan key baru (08 §7.1 "LY-04 tampil lagi tepat sebelum perintah itu"). Sesudah `CompleteSignUp`, LY-04 langsung tampil. `AGE_DECLARATION_VERSION = 1` di `copy.ts`, di samping kalimatnya.
10. **Idempotency key per niat** (ADR-005; 09.2 §8): `crypto.randomUUID()` pada kiriman pertama formulir, dipakai lagi selama permintaan sama (coba lagi sesudah gagal jaringan), dan diganti bila isian berubah atau sesudah penolakan aturan.
11. **Bantuan panjang nama** (FAM.md FR-FAM-001 catatan bentuk isian): `visibleLength` meniru hitungan `household.CleanName`: pangkas dengan himpunan `unicode.IsSpace` Go (bukan `trim()`, yang berbeda di U+0085 dan U+FEFF), NFC, lalu hitung code point selain `\p{Mn}`, `\p{Me}`, dan U+200D. Kelas karakter SEC-155 (h) tetap aturan server. Batasnya `HOUSEHOLD_NAME_MAX = 60` dan `DISPLAY_NAME_MAX = 40`.
12. **Urutan vektor emas:** aturan dan kasus tangan di PR C; pemakai berkas vektor di PR F, segera sesudah PR C rencana 1.7 di-merge (14 §4.5 "Gerbang").
13. **Rute:** jalur tautan mengikuti server (`/signup`, `/signup/verify`, `/invite`); rute layar dan judulnya menurut tabel judul 08 §7.6. `/` memilih layar dan menjadi layar rumah tangga bagi anggota.
14. **Layar rumah tangga menggantikan LY-20 di langkah 1:** satu kolom, `h1` nama rumah tangga (08 §6.1 bagian 0), anggota, dan pintu ke LY-07 atau LY-08 menurut `GetOpenInvitation`. Dikukuhkan 08 §7.6 (`home.*`).
15. **Mengetahui perubahan tanpa sinkron:** `GetOpenInvitation` (layar rumah tangga) dan `ListMemberships` (layar menunggu) saat dibuka dan saat `visibilitychange` terlihat, `user_initiated: false` (FAM.md FR-FAM-004 catatan). Diganti sinkron di 1.9b bagian 2.
16. **Bagikan:** `navigator.share({ text })`, atau `navigator.clipboard.writeText` dari ketukan yang sama bila tidak tersedia. Teks dari §7.3. Token hanya di variabel komponen (SEC-28 catatan Q7 (d)). Membagikan lagi berarti `IssueInvitationLink` baru.
17. **Teks layar di `web/src/lib/copy.ts`**, dengan kunci 08 §7.6 sebagai nama; uji menulis kalimat 08 sebagai literal, tidak mengimpornya. Judul halaman dari tabel judul 08 §7.6 (SEC-175 (a)).
18. **Tanpa dependensi uji baru** (tanpa testing-library, jsdom, axe): komponen diuji lewat halaman; `layout.spec.ts` memeriksa yang murah, selebihnya QG-09.
19. **Uji alur memakai `serviceWorkers: 'block'`**, karena `page.route` tidak melihat permintaan yang ditangani service worker.
20. **ID di nama uji:** ID AC hanya bila uji klien membuktikan seluruh AC; selain itu ID FR atau SEC (putusan lead 1.6 menggantikan butir 11 putusan 1.9a).
21. **LY-06:** tanpa hari mulai sampai langkah 3; nama tampilan wajib (FR-FAM-006; 08 §7.6 mengukuhkan keduanya).
22. **LY-05:** label "Berlaku saat fitur ini tersedia" tampil bila `feature` tidak kosong dan tidak ada di `BUILT_FEATURES` (kosong di langkah 1). Baris "Pemberitahuan ini berubah…" hanya bila LY-05 dibuka dari tahanan `NOTICE_UNREAD`. Ini sementara: Task 13 menggantinya dengan `earlier_version_acknowledged` (09.3 §1, catatan 14 November 2026), yang juga benar bagi versi yang terbit saat aplikasi tertutup.

## Batasan global

- Batasan global 1.1b dan 1.9a berlaku: tanpa `localStorage`/`sessionStorage`, tanpa token tersimpan, log tanpa isi (ES §4), daftar bundel tertutup, versi tepat, `minimumReleaseAge: 10080`.
- **Kontrak hasil generate saja**; `web/src/lib/gen/` tidak disunting; perubahan kontrak lewat lead.
- **Tanpa sink HTML** (SEC-167): teks server (nama rumah tangga, nama tampilan, paragraf pemberitahuan, email) dirender sebagai teks Svelte biasa.
- **Mode bersama tidak menulis apa pun** (SEC-165 (b)): `localDb()`, `registerServiceWorker()`, `requestPersistence()` hanya di mode pribadi.
- **`user_initiated`** (SEC-165 (g)): `true` untuk RPC dari ketukan dan navigasi pengguna, `false` untuk pemeriksaan sesi saat dibuka dan pembacaan saat `visibilitychange`.
- **Teks layar** dari 08 kata demi kata (kunci 08 §7.6), tidak dikarang; tanpa kosakata akuntansi; "perangkat", bukan "ponsel" (W-5).
- **Bentuk:** elemen HTML bawaan dulu (W-3); satu komponen per pola (WS-4); 390, 744, 1133, 1280 px, terang dan gelap; sasaran 48 px; fokus ke `h1` sesudah navigasi (08 §25.5).
- **Nama uji** diawali ID (literal di `test(`); Vitest `web/src/**/*.test.ts`, Playwright `web/tests/e2e/*.spec.ts` di kedua mesin; tanpa `test.skip` per mesin tanpa persetujuan lead.
- **Pengenal** memakai nama kontrak (`invitation`, `invitee`, `operator notice`, `device mode`, `display name`) dan glosarium.

## Fokus tinjauan

1. **Token tautan bocor:** permintaan pertama sesudah `/invite#t` atau `/signup#t` terjadi sesudah hash kosong; di tab Safari iPhone atau iPad tidak ada permintaan berisi token sebelum ketukan jalan mode bersama (10.5 SEC-171 (b) (3), Q4-2). Uji `SEC-175 (c): an invitation link's token leaves the address bar before the first request` di Task 11.
2. **Jejak mode bersama:** tidak ada basis data, service worker, Cache Storage, atau web storage. Uji `SEC-165 (b): after a shared-mode sign-in nothing is stored and no service worker is registered` di Task 5.
3. **Server lambat atau luring saat dibuka:** tertahan paling lama 3 detik, memeriksa ulang saat tersambung. Uji `SEC-172 (b): the app waits at most 3 seconds for the session check, then checks again when back online` di Task 2.
4. **Ketukan ganda dan coba lagi:** key sama sesudah gagal jaringan, ketukan kedua tidak mengirim, isian berubah memakai key baru. Uji `ADR-005: retrying a failed create reuses its idempotency key; a changed name gets a new one` di Task 9.
5. **Sesi dicabut saat data tampil di dua tab:** keduanya menampilkan LY-94 dan nama rumah tangga hilang dari DOM. Uji `SEC-172 (a): a session_revoked answer on the household screen removes the household name from every tab` di Task 9.

## Pratinjau di perangkat pilot (disetujui pemilik produk, Q5)

Service worker, `crypto.subtle`, Web Locks, cookie `__Host-`, dan `persist()` memerlukan HTTPS yang dipercaya; `http://192.168.x.x` menampilkan LY-97. Sesuai "jalan di pc saya aja dulu":

1. `casa serve -listen 127.0.0.1:8080 -origin https://<IP-LAN-PC>:8443 -mail-dir <dir>` dengan basis data `casa-postgres-web`.
2. `caddy reverse-proxy --from https://<IP-LAN-PC>:8443 --to 127.0.0.1:8080 --internal-certs`: CA lokal dan sertifikat untuk IP itu; `Origin` diteruskan apa adanya.
3. Sertifikat akar CA lokal Caddy (`~/.local/share/caddy/pki/authorities/local/root.crt`) dipasang sementara:
   - **iPhone dan iPad:** pasang profil, lalu Pengaturan › Umum › Info › Pengaturan Kepercayaan Sertifikat › nyalakan;
   - **Galaxy A55:** Pengaturan › Keamanan › Pasang sertifikat CA.
4. Surat verifikasi ditulis sebagai berkas di `<dir>`; tautannya dibuka dari situ.
5. Sertifikat dicabut dari ketiga perangkat begitu WS-5 ada. Risiko: pemegang kunci CA dapat menyamar sebagai situs mana pun bagi perangkat itu, jadi kunci tidak keluar dari PC.

Skripnya `web/scripts/preview-lan.sh` (Task 12). Pemeriksaan perangkat masuk lingkup setiap PR layar (Task 16 langkah 5).

### Task 1: Klien connect-web, versi klien, dan pembaca galat

**Berkas:** buat `web/src/lib/api.ts`, `web/src/lib/api.test.ts`; ubah `web/package.json` (`version`, dua dependensi), `web/pnpm-lock.yaml`, `web/vite.config.ts` (`define`), `web/src/app.d.ts` (deklarasi `__CASA_VERSION__`).

**Antarmuka (menghasilkan):**
- `export const CLIENT_VERSION: string`
- `export function createApi(transport: Transport): { identity: Client<typeof IdentityService>; household: Client<typeof HouseholdService> }`; `export const api = createApi(webTransport())`, dengan interseptor `clientIdentity` yang menimpa `client_kind = CLIENT_KIND_WEB` dan `client_version = CLIENT_VERSION` dan membiarkan `user_initiated` serta `idempotency_key` dari pemanggil.
